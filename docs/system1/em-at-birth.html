When extraction meets a name it has not seen — a descriptive phrase ("the silver-haired girl") or a name fragment ("美琴" for 御坂美琴) — it does not mint a new entity first and sort it out later. Identity is resolved at birth: one strict Jev round checks whether the candidate belongs to someone already in the graph. Only true newcomers mint. This is decision #18's first layer, and it runs inside the Digger, while the block is still being dug.

InputsA candidate (descriptive text or name form) + the existing entities + the scene it appeared in
OutputsEither an alias attached to an existing entity (confidence ≥ 0.85), or a newly minted entity; variant spellings recorded as forms, stored names never rewritten

Design details

  • Reading beats derived features: the identity pass reads the passage first. Structural features inherit extraction noise, so they are the backstop (09a), not the first check.
  • One strict round: a descriptive candidate gets exactly one strict Jev round; at confidence ≥ 0.85 the description attaches as an alias. Below that, it stays a candidate — the global pass will re-check it later.
  • Fragments fold at birth: a name fragment folds through a variant-folded containment trigger plus the same strict Jev round. The round is load-bearing: naive substring folding can mis-attach ("美琴" is safe; a bare shared character is not).
  • Names are never rewritten: variant spellings resolve through the language-map fold (decision #19) and are recorded as forms. The stored name stays exactly as the novel wrote it.
  • Transient figures stay out: the transient rule (decision #8) still applies — an unnamed figure with no setup behind it is not minted, even if it arrives with a description.

Implementation

  • src/digger/extraction/extraction.ts — extraction mints through mintEntity with aliases attached; descriptive candidates arrive flagged (descriptive: boolean) in the scene result, and alias proposals (add_alias) are separated from new-entity proposals before the ChangeSet is built.
  • src/solidifier/matching/fragmentMatch.ts — containmentTargets: the variant-folded containment trigger for fragment candidates.
  • src/solidifier/matching/entityMatch.ts — CONFIDENT_THRESHOLD = 0.85: the attach bar for the strict round. The formToId registry is keyed by the language-map fold, so variant spellings resolve at ingest instead of minting duplicates.
  • Birth output reaches the reviewer as ordinary identity facts under the shared staged review gate (sector 09, decisions #17 + #26) — it is not a side channel around the gate. Identity facts there show readable labels, and the reviewer can apply label-based semantic replacements instead of editing ids by hand.

Open questions — EM at birth

  • Birth-order races.Two candidates for the same person can arrive in the same block before either is attached. Known v1 limit; the global pass (09a) is the current safety net.
  • Guarding the cast-name mint path.Extraction's unguarded cast-name mint path should get the same fragment round (v2). Spec written, awaiting ratification.
  • Cross-script pairs.安娜 vs "Anna Sprengel" cannot fold through the language map — co-presence nomination is the open design item, shared with 09a.
