Library & universes — many files, one organization

status: implemented (universe phase 1) repo: src/ground/workspace/library.ts · src/solidifier/merge/identityLabels.ts · src/solidifier/causality/universe.ts model: main agent + Jev (label-based)

One user has many files: volumes of a series, sequels, side stories, shared worlds. The library organizes them without fusing them. Sources are content-addressed, membership is evidence-gated, every file keeps its own isolated workspace — and identity across files is handled fail-closed, with readable labels the reviewer can actually correct.

Design details

  • Content-addressed sources: each source gets an id from its content hash (doc_<sha256>). The same file twice is the same document; a changed file is a new document. The versioned catalog.json records universes → continuities → series → assignments, each confirmed or unresolved — unresolved assignments stay outside scoped results.
  • Evidence-gated plans: a membership or ordering plan is only as good as its quotes, and quotes are verified at exact offsets before anything is decided. prepare builds an isolated per-source workspace and does none of: model calls, ingestion, identity merging. Ingest, recall and album binding all route through the workspace's ontology/source.json.
  • Isolation is the point: block ids restart at b0001 per file, so multi-source workspaces that shared ids would collide. The library refuses shared-workspace multi-file ingestion outright and cites that collision — federation, not fusion, is phase 1.
  • Fail-closed semantic identity (decision #24): Jev and the main agent see readable labels, and code resolves labels to ids. Ambiguity fails closed instead of guessing. The gate shows a meaning per fact and accepts label-based semanticReplacement corrections; relation-endpoint edits are refused. Jev handling hardened alongside: an invalid or missing noul throws instead of defaulting to 0, there is no retry on malformed responses, and missing, duplicate or out-of-range scores force uncertain / held. Duplicate-proposal-id repair is audited.
  • Universe causal ledger, separate by design: cross-file causal nomination is name-hint only — deliberately no embedding leg, unlike the within-file hybrid search (09b). A Jev sweep over the nominated pairs feeds independent review; accepted links go to a separate audited ledger (<library>/causality/state.json) with source-qualified endpoints (doc_id::unitId), cycle refusal, and bookDatabasesModified: false — per-book databases are never fused.
  • What phase 1 defers: a story-time / universe timeline faculty (phase 2), cross-book EM, and shared-workspace multi-file ingestion. The main agent calls cross-file causality after a full run; the systematic path stays within one file.
