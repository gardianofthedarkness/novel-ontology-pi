Digging a tunnel through a novel

novel-ontology-pi turns a novel into a living ontology — characters, events, timelines that can fork. The product has four parts: a Skill that teaches an agent the workflows, a CLI that does the work, one Adaptor that makes both installable into any popular agent host, and a Frontend where the work is watched. Inside the CLI, data extraction is told the way tunnels are built: the ⛏ Digger (miniloop + faculty graph) chews through the raw earth of the text and advances along the timeline; the 🧱 Solidifier (merge-gate review, EM, cross-sectional EM) lines the tunnel behind the face so what was dug becomes permanent canon. The simulation group is kept — deliberately empty for now.

The hierarchy — one picture

Rule zero: never ask a model what code can compute exactly. Sectioning, offsets, and scanning for known names are code. Jev is only asked genuinely ambiguous questions — and it answers with probabilities, not text, batched: one call per window, all questions at once. The one hard boundary in the picture: nothing crosses from ChangeSet to storage except through the Solidifier, on approval. And the Digger never waits for the Solidifier to finish the whole tunnel — it digs the next block while the last one is being lined.
