12State materialization semantics (2026-10-22)Decision #10 implemented: set_state_change deltas persist as first-class bundle records (state-changes.jsonl) and add_alias materializes at apply — deferred count for both kinds drops to zero and changeset.merged fires truthfully again. Character state is fold-on-read (never a stored row; snapshots only if a real query ever feels slow). Emotions and relationships are ADDITIVE deltas, clamped to [-1, 1] (owner's explicit call); knowledge/goals/possessions are set add/remove, location replaces on non-null. Read surface: novel state <dir> <character> [--at <event>]. This is the snapshot machinery Phase 4 simulation will consume.✓ decided
11Segmentation by span selection (2026-10-22)Scenes: Jev chooses where scenes START over 80-sentence batches (20 look-back); a scene's end is defined by the next chosen start, so scenes tile the block exactly (start = last end + 1). Per-scene end-picks are cross-checks; an open scene at a batch seam gets ONE continuation query with its tail text injected ("ended" ratifies its provisional end). Dialogue: exchanges (not lines) via start+end selection, stitched on ≥3-sentence overlap, each linked to one scene — or two when the conversation straddles a cut; turns live inside exchanges. Measured: 77 scenes (median 1) → 10 scenes, exact partition, on the same 15K chars; the 6K prologue went from 32 scenes / 364 proposals to 4 scenes / 99. Retires the per-sentence boundary/kind questions.✓ decided
10Character state model (2026-10-22)Every character is a state machine: state (six dimensions from sector 08) evolves as a chain over chronological time — state at any point = the deterministic fold of all canon state deltas up to that point. Folding canon is not stochastic (it happened); stochastic sampling enters only in simulation, generating forward from a folded snapshot (Phase 4). Materializing the deferred set_state_change proposals into this chain is the prerequisite build.✓ decided
6Playground frontend (sector 13)Reagraph (React, true 3D, clustering/badges built in) + React Flow pipeline strip; standalone-first, host-agnostic — a VS Code webview wrap stays possible later; extension-host research concluded no existing app provides this for free✓ decided
13Miniloop pipelining (2026-10-22)Blocks stay sequential (registry, counts, presence carry-over), but within one block the independent Jev pipelines run concurrently — block cost = the longest pipeline, not the sum. Stage 1 (PR #27): scene tiling ∥ dialogue selection ∥ name refinement; exchange→scene links are a pure join after all pipelines land. Presence across windows, speaker (needs same-window presence), and extraction (cast threading) stay sequential — true dependencies, not accidents. Measured: 15K miniloop 65s → 44.7s (−31%), same quality.✓ decided · stage 1 built
14Eval matching keys (2026-10-22)Ratified by the merge of PR #18: two-pass matching (exact id, then semantic-key multiset) with keys — entity = kind + canonical name; event = timeline + whitespace-normalized summary; relation = type + resolved endpoint keys. These keys are the format of record: changing them breaks score comparability across runs. Accepted consequence: real-ingest event scoring is summary-text-exact (strict, deterministic).✓ decided

Clicking agent activity shows new nodes emerging in place, batch by batch, as processing pushes the timeline forward — the working-draft stream (PR #19) rendered in the layered/orbital explorer, ghosts first, resolving on gate verdicts; held/revised proposals get a distinct ghost state. The activity tab accumulates and shines (escalations immediately, verdicts batched silently); agent activity never steals the camera — clicking flies the user to where the agent and System 1 are knitting. Build started 2026-10-22 (Phase B); landed 2026-10-23 as PR #31 (supersedes #28), adapted to the streaming-faculty pipeline (decision #16): legacy miniloop, extraction and faculty batches (scene-closed / dialogue-structure / grounding-assembly) all announce through the one serialized publish funnel, and the draft projector renders them in the explorer. Merged tree verified 199/199 + playground build + scripted faculty live proof (26 draft.updated batches before the gate).✓ decided · built (PR #31)
16Streaming faculties — the pool system (2026-10-23)Live ingestion with a work model now runs a dependency-aware faculty graph (PR #30, merged 2026-10-23; design in docs/faculty-graph.md). Jev keeps scene segmentation and dialogue structure; as each scene closes, scene-local faculties stream concurrently — identity/participants, scene understanding (summary, events, state observations), dialogue alignment, then speaker/turn attribution — under one shared pool (4 concurrent calls, 1 slot reserved for adjudication, 256-call per-block budget, in-run caching only). Bounded System 2 adjudication: unpinned scene choices under 0.85 and speaker choices under 0.80 (routing thresholds, not calibrated probabilities; originals preserved in review notes) get ONE scoped LLM adjudication constrained to the offered options; unresolved speakers stay null. Assembly is deterministic and source-ordered; no faculty output approves or writes canon — the Pi gate is unchanged, state remains the deterministic fold, and continuity previews are explicitly unapproved. Legacy pins (name/presence/window-speaker) route the block to the legacy path with an explicit note; the legacy path also stays available via facultyGraph: false. This supersedes decision #13's hand-scheduled stage-2 overlaps. Small-batch benchmark (493-sentence prologue, 193-sentence annotated sample): strict speech precision 38.7% → 94.1%, named-speaker sentences 0/38 → 30/38, latency −29% — at 3.82× work-model tokens (quality bought with tokens, disclosed; full-volume numbers pending). Scene gains an optional summary field (original language, decision #7).✓ decided · built (PR #30)
