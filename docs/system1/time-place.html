Time & place — when and where scenes happen

status: implemented (phase 1) repo: src/digger/timeplace/ model: Jev roles + work-model vocabulary

Scenes already tile the block (02) and carry a cast (05). This faculty answers the next two questions for each scene: when does it happen, and where? Time words become entities that scenes belong to — a TimePoint holds the words as written, a normalised value, its role, a flashback mark with Jev's certainty, the period it was told from, a stated or derived date, and an estimated story order. Place words attach scenes to Location entities. Granularity is the scene: one scene, one period, one place.

InputsNew scenes + their sentences (after the block's main ChangeSet applies) + the time/place lexicon
OutputsTimePoint entities · Scene -OCCURS_DURING→ TimePoint (via anchor or inherited) · Scene -LOCATED_AT→ Location · storyIndex estimates
Depends on02 Scene spans, 01 Sectioning (sentence IDs anchor every mention)
Feeds into09 Merge gate (its own pending-review ChangeSet) · 13 Story time and Places views

Design details

  • TimePoint is an entity, not a label: expression, family, value, gloss, role, flashback, flashbackProbability, decidedBy, confidence, toldFromId, date, partOfDay, sentenceId, sceneId, chapterIndex, narrativeIndex, storyIndex, source. Its id is time_<sentenceId>_<start> — anchored to the sentence that said it.
  • Jev decides roles, one question per scene: each checkable mention gets time_role — ADVANCE / FLASHBACK / RETURN / REFERENCE ("choose REFERENCE when unsure") — plus a continuation question at each scene break after a flashback (CONTINUES_FLASHBACK vs RETURNS_TO_PRESENT). Thresholds are new policy, distinct from the 0.85 standard (decision #25): flashback 0.6, advance 0.5, soft-advance 0.6, past-marker probability 0.5.
  • Below threshold, the Jev path fails closed: a sub-threshold FLASHBACK/ADVANCE/RETURN verdict downgrades to REFERENCE (recorded as downgraded), and unrecognised Jev values default to REFERENCE. Known gaps, stated honestly: rule-decided and heuristic paths bypass Jev thresholds, null confidence passes ADVANCE/RETURN, and continuation has no threshold — a below-threshold unit test and an explicit continuation call are still owed.
  • Story order is an estimate, never the timeline: orderStory (pure code) puts the present line in reading order and each flashback before its host (dated flashbacks before the first later-dated present period, otherwise before toldFromId). It is stored as a separate field: narrativeIndex preserves reading order, storyIndex carries the estimate. Nothing touches chronological order, PRECEDES, or novel sequence — novel sequence remains the timeline for v1, and story order is labelled estimated everywhere it is shown ("dates marked *derived* are calculated from stated words, never guessed"). Story order is never treated as causation.
  • Vocabulary is a work-model list, not a prompt change: the work model lists time/place words verbatim from the text; no existing extraction prompt is edited. Code validation (spans must occur verbatim in their sentence; bare connectives and quantity-less spans rejected) runs before the reviewer gate. Quoted places are dropped, not counted as mentions.
  • The gate is preserved: the faculty runs after the main ChangeSet is approved and applied, over scenes without OCCURS_DURING, and its proposals go through a pending-review ChangeSet and the same reviewer — never straight to canon, never auto-approved. Failures only write a review note and never block ingestion.
  • Storage asymmetry, stated plainly: the bundle JSONL is the full record, but Ladybug stores only the TimePoint id and the bare OCCURS_DURING edge — via, flashback, storyIndex, date and flashbackProbability live only in the bundle, so Cypher cannot see them yet. No in-place migration exists for an existing graph.lbug (rebuild from the bundle); a forced re-run can strand stale memberships, because dedupe suppresses re-proposal but never deletes. New Location minting matches exact normalised forms only — a variant spelling can mint a duplicate, since there is no variant fold or EM nomination on this path.

Implementation

  • src/digger/timeplace/faculty.ts — proposals; lexicon.ts (Chinese-first, basic Japanese/English) · periods.ts (assembly + story ordering) · roles.ts (Jev roles + thresholds) · vocabulary.ts (work-model word list) · cache.ts · afterApply.ts (post-apply hook).
  • CLI: novel ingest --time-place · novel timeplace run|show. Schema: TimePoint + OCCURS_DURING in src/ground/ontology/; LOCATED_AT is pre-existing and reused.
  • Tests: 12 new time-place tests + 2 projection tests (docs/time-place.md).

Open questions — time & place

  • Below-threshold coverage.A unit test asserting below-threshold → REFERENCE + downgraded (including null-confidence and Jev-failure fallback) is owed, as is an explicit statement of the continuation no-threshold choice.
  • Cross-volume time.Within-novel scene time is phase 1. Cross-volume temporal reconciliation and a universe timeline faculty are phase 2 (see 11) — storyIndex estimates must not be mistaken for a shared chronology.
  • Other genres and languages.The lexicon is Chinese-first with basic Japanese/English; measured accuracy claims so far are tuning data, not blind results.
  • Ladybug parity.Should storyIndex, dates and flashback probability be queryable in Cypher, or does the bundle remain the only full record? A schema decision for the next phase.
